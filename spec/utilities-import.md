# 光熱費取込機能 仕様書

作成日: 2026-11-17
ステータス: 実装完了(v0.10.1、`docs/index.html` に実装済み)

## 1. 背景・目的

電気代・ガス代を毎月手入力する手間をなくすため、Claudeの定期実行(毎月20日 21:13)が
「ほくでん エネモール」から請求データを取得し、取込用ファイル(JSON)を
**Googleドライブに直接保存する**。利用者は本アプリの「光熱費取込」で
ドライブ上のファイルを選んで読み込む。

(1.0版ではファイルをチャットに送付し、利用者がスマホに保存する運用だった。
1.1版でGoogleドライブへの直接保存に変更)

## 2. データの流れ

| 手順 | 担当 | 内容 |
|---|---|---|
| 1 | 定期実行 | エネモールの契約一覧→各契約の請求のお知らせから請求月・確定日・使用量・金額を取得 |
| 2 | 定期実行 | 全期間分を `spending-log-utilities-YYYYMMDD.json` として出力し、Googleドライブの `Spending-Log/光熱費` フォルダに保存(チャットには保存結果のみ報告) |
| 3 | 利用者 | アプリの⚙→「光熱費取込」→ファイル選択画面でGoogleドライブを開き、最新のファイルを選択→確認ダイアログでOK |
| 4 | アプリ | id単位で追加/更新(upsert)。手入力の記録には触れない |

### Googleドライブ保存の前提
- 定期実行を行うclaude.aiのチャットで、Googleドライブのコネクタが接続されていること
  (ファイル作成ツールで保存する)
- 保存先フォルダ `Spending-Log/光熱費` が無い場合は定期実行側で作成する
- ファイルは毎回日付付きの新しい名前で保存する(上書きはしない)。各ファイルは
  全期間分を含むため、取込時は最新の1ファイルだけを選べばよい
- 保存に失敗した場合は、従来どおりチャットにファイルを送付してフォールバックする

### 運用方針(2026-11-18 決定)
- **記録の正本はスマホのsp-log**。手入力の記録も光熱費もスマホに集約する
- PC(Claude Codeの定期実行)は取得と保存だけを担当し、sp-logへの取り込みはしない。
  保存先はGoogleドライブ `Spending-Log/光熱費` と、PC内の `import/`(`.gitignore` で除外)の2か所
- 利用者は毎月1回、スマホの⚙→「光熱費取込」でドライブの最新ファイルを読み込む
- PCとスマホの記録を突き合わせる運用(バックアップを全置き換えで復元してから光熱費を取り込み直す)は、
  手順が多く記録を消す恐れがあるため採用しない

### スマホでのファイル選択
- Android: ファイル選択画面のメニューから「ドライブ」を選べる
- iPhone: Googleドライブアプリをインストールし、「ファイル」アプリの「場所」で
  Googleドライブを有効にしておくと、ファイル選択画面から選べる
- アプリ側の取込処理は変更不要(通常のファイル選択で読み込める)

## 3. ファイル形式

```json
{
  "type": "spending-log-utilities",
  "version": 1,
  "generatedAt": "2026-11-17T22:20:00+09:00",
  "items": [
    { "id": "util-electric-2026-10", "date": "2026-10-20", "subCategory": "電気代",
      "amount": 5000, "memo": "10月分 100kWh 9/1-9/30", "status": "確定", "source": "ほくでんエネモール" }
  ]
}
```

| 項目 | 内容 |
|---|---|
| type | `spending-log-utilities` 固定(バックアップファイルとの取り違え防止) |
| id | `util-<electric/gas/water>-YYYY-MM`(請求月)。同じ請求月は常に同じid |
| date | 請求確定日(エネモールの請求のお知らせの発行日)。予定額は予定発行日 |
| subCategory | 電気代 / ガス代 / 水道代 のいずれか |
| amount | 請求額(円・正の整数) |
| memo | 「M月分 使用量 使用期間」。予定額は末尾に「(予定)」。50文字で切り詰め |
| status / source | 参考情報(アプリでは未使用) |

## 4. 取込ルール

| ケース | 動作 |
|---|---|
| idが未登録 | 大項目「光熱費」で新規追加 |
| idが登録済みで内容が異なる | 日付・金額・メモ・小項目を上書き(予定→確定の更新を想定) |
| idが登録済みで内容が同じ | 何もしない(何度取り込んでも重複しない) |
| 同じ月・同じ小項目に手入力の光熱費がある | 確認ダイアログで二重計上の可能性を警告(取込は可能) |
| type不一致・不正データを含む | 取込を中止しエラー表示(1件でも不正なら全件中止) |

- 取込前に「追加n件 / 更新n件 / 変更なしn件」を確認ダイアログで表示する
- 取り込んだ記録は通常の記録と同様に編集・削除できる。ただし編集後に同じidを再取込すると上書きされる
- 水道代はWeb取得できないため、当面は手入力。将来、検針票の金額をチャットで伝えて
  ファイルに含める運用も可能(id: `util-water-YYYY-MM`)

## 5. UI

- ⚙の設定モーダル(タイトル「データ管理(バックアップ/光熱費取込)」)に、説明文と
  「光熱費取込(ファイルを選択)」ボタン(光熱費の緑)を追加
- 結果はモーダル下部のメッセージ欄に表示
