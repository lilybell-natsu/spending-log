# データのバックアップ/復元機能 仕様書

作成日: 2026-08-24
ステータス: 実装完了(v0.9.0、`docs/index.html` に実装済み)

## 1. 背景・目的

本アプリはデータをブラウザの `localStorage` にのみ保存しており(README記載の
通り、複数端末・複数利用者間の同期はフェーズ2で検討中)、機種変更やブラウザの
キャッシュ削除で記録が失われるリスクがある。姉妹プロジェクトの
[fuel-log](../../fuel-log/index.html)(給油記録アプリ)に実装済みの
「データのバックアップ/復元」機能と同じ方式を、本アプリにも追加する。

## 2. 参考にした実装(fuel-log)

`C:\Users\harun\Desktop\Claude\app\fuel-log\index.html` の実装を確認し、
同じ設計方針を踏襲する:

- ヘッダーに⚙(歯車)アイコンボタンを配置し、タップで設定モーダルを開く
- モーダル内に「エクスポート」「インポート」の2ボタン
  - エクスポート: 保存データ一式をJSONファイルとしてダウンロード
  - インポート: JSONファイルを選択→内容を検証→確認ダイアログ→全置き換え
- ファイル名は `<アプリ名>-backup-YYYYMMDD.json` の形式
- インポートは全置き換え(差分マージはしない)。誤操作防止のため
  `confirm()` で確認を挟む

fuel-logは車種(`cars`)を含む複雑なデータモデルだが、spending-logは
`records` 配列のみとシンプルなため、エクスポート対象もそれに合わせて
簡略化する。

## 3. データ形式

```json
{
  "version": 1,
  "exportedAt": "2026-08-24T12:34:56.789Z",
  "records": [ { "id": "...", "date": "...", "category": "...", ... }, ... ]
}
```

- `records`: 既存の `records` 配列(localStorageキー `spendingLogRecords_v1`)をそのまま格納
- `version`: 将来のフォーマット変更に備えたバージョン番号(現在は1固定)
- `exportedAt`: エクスポート日時(ISO8601)。参考情報でありインポート時には未使用

## 4. UI・操作フロー

```
[⚙アイコンをタップ] → [設定モーダルが開く]
  → [エクスポート] → JSONファイルがダウンロードされる
  → [インポート] → ファイル選択 → 内容検証 → 確認ダイアログ
      → OKなら現在の記録を全置き換え、カレンダーを今日の月に戻して再描画
```

- ヘッダー右上に⚙アイコンボタンを追加(`#settingsBtn`)
- 設定モーダル(`#settingsModal`)は既存のモーダル共通スタイル
  (`.modal-overlay` / `.modal-sheet` / `.modal-head`)を流用
- エクスポートボタン: `exportData()` が `records` をJSONにシリアライズし、
  Blob + `<a download>` でファイルをダウンロードさせる
- インポートボタン: 非表示の `<input type="file">` をトリガーし、選択された
  JSONファイルを `FileReader` で読み込み、`importDataFile()` で処理
- インポート成功・失敗のメッセージをモーダル内に表示

## 5. バリデーション・エラーハンドリング

| ケース | 挙動 |
|---|---|
| JSONとしてパースできない | 「ファイルの読み込みに失敗しました。正しいバックアップファイルか確認してください。」 |
| `records` が配列でない/存在しない | 「バックアップファイルの形式が正しくありません。」 |
| ファイル読み込み自体の失敗(`FileReader.onerror`) | 「ファイルの読み込みに失敗しました。」 |
| 上記いずれも通過した場合 | `confirm()` で「現在の記録をすべて置き換えます。よろしいですか?」と確認 |
| 確認後 | `records` を置き換え、`saveRecords()` で保存(内部で再描画も行われる)、表示月を今日の月にリセット、「復元しました。」と表示 |

## 6. データモデルへの影響

なし。既存の `records` 配列の形式・localStorageキーは変更しない。
インポートされたデータは既存の `records` 変数へそのまま代入し、
`saveRecords()` で保存する(既存の保存ロジックを再利用)。
