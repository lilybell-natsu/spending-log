# レシート読取機能 仕様書

作成日: 2026-08-22
ステータス: 実装完了(v0.6.1、`docs/index.html` に実装済み)

## 1. 目的・ユーザーフロー

現在の記録フローは「日付→大項目→小項目→金額(手入力)→メモ→記録」。
このうち金額入力の手間を減らすため、レシート画像から金額を自動読取する機能を追加する。

```
[レシート画像を読み込む] → [OCRで金額を読み取る] → [大項目・小項目を選択] → [記録]
```

- 入力/編集モーダル(`#entryModal`)に「レシート読込」ボタンを追加
- タップすると端末のカメラ起動 or 写真選択(`<input type="file" accept="image/*" capture="environment">`)
- 選択後、自動でOCRを実行し金額欄に候補値を自動入力
- **自動入力された金額は必ずユーザーが目視確認・修正できる状態にする(自動記録はしない)**
  読み取り精度は完全ではないため、金額欄への反映はあくまで「入力の補助」であり、
  その後の大項目・小項目選択、記録ボタン押下は既存フローのまま変更しない

## 2. 検討した方式と選定理由

| 方式 | 概要 | 採否 | 理由 |
|---|---|---|---|
| クラウドOCR API(Google Cloud Vision, Azure等) | 画像をAPIに送信しテキスト抽出 | ✕ | 本アプリはバックエンドなし(README記載の通りフェーズ2で検討)。クライアントのみの公開HTMLにAPIキーを埋め込むと第三者に抜き取られ悪用されるリスクがあり、個人開発の家計簿アプリの規模には見合わない |
| ブラウザ標準 Shape Detection API (`TextDetector`) | ブラウザ組込みのテキスト検出 | ✕ | 仕様が事実上非推奨・実装がChromiumの一部にしかなく、本アプリが重視するiOS Safariでは利用不可のため対象外 |
| **クライアントサイドOCR(Tesseract.js)** | 端末内(ブラウザのWASM)でOCRを実行 | **採用** | バックエンド不要、画像は端末外に一切送信されない(プライバシー面で家計簿アプリに適する)、iOS Safariでも動作する |

### 採用方式: Tesseract.js

- CDN経由で動的に読み込む(初回のレシート読込ボタン押下時のみ。通常のアプリ起動時にはロードしない=既存の軽量な初期表示を維持):
  `https://cdn.jsdelivr.net/npm/tesseract.js@5/dist/tesseract.min.js`
- 言語データは日本語(`jpn`)を指定して認識
- 画像・OCR処理は完全に端末内(ブラウザのWASM/Worker)で完結し、外部サーバーには一切送信されない

## 3. 動作検証(プロトタイプ)

日本語混じりの合成レシート画像(canvas生成、「小計」「消費税」「合計」「お預り」「お釣り」を含む)に対し、
実際にTesseract.jsでOCRを実行して検証した。

**入力画像の内容(抜粋):**
```
小計          ¥750
消費税(8%)     ¥60
合計          ¥810
お預り        ¥1,000
お釣り          ¥190
```

**OCR認識結果(抜粋、実行時間 約4.9秒):**
```
小計 \750.
消費 税 (8%) _\60
合計 \810
お 預り \1,000
お 釣り \190
```

**下記の抽出ロジックによる結果: `810`(正しく「合計」の値を抽出。小計750や
お預り1,000ではないことを確認)**

→ 日本語混じりのレシートでも、数字部分の認識精度は高く、キーワードベースの
抽出ロジックと組み合わせることで実用的な精度が得られることを確認した。
(文字部分の認識は完全ではない=店名や品目名の誤認識はあるが、金額抽出には影響しない)

## 4. 金額抽出ロジック(v0.6.1で座標ベースに変更)

初版(v0.6.0)ではOCRテキストの改行(行)単位でキーワード行を探す方式だったが、
ラベルと金額の間に大きな空白があるレイアウトで行がずれることがあり精度が低かった。
v0.6.1では、OCRが返す**単語ごとの座標(bbox)**を使い、「合計」の文言と**同じ行
(Y座標が近い)**にある金額を最優先で抽出する方式に変更した。
「一番大きい数字を採用する」のではなく、あくまで「合計の横にある金額」を優先する。

1. 全角数字を半角に正規化
2. `data.words`(Tesseract.jsが返す単語ごとの認識結果、各々`bbox:{x0,y0,x1,y1}`を持つ)
   から `合計` `合計金額` `総合計` `お会計` のいずれかを含む単語を探す
3. そのキーワード単語のY座標(中心)を基準に、同程度のY座標(同じ行とみなせる
   許容誤差内)にある他の単語を左から右の順に確認し、最初に見つかった
   金額らしい数値(10〜1,000,000の範囲)を採用する
4. 座標データが無い、または上記で見つからない場合のフォールバックとして、
   OCRテキストの改行(行)単位でのキーワード一致→それでも無ければ
   テキスト中の数値の最大値、という初版(v0.6.0)のロジックを使う
5. 該当なしの場合は金額欄を空のままとし、「金額を読み取れませんでした。
   手入力してください」を表示

```js
// 座標(bbox)ベースの抽出(最優先)
function extractAmountFromWords(words){
  if(!words || !words.length) return null;
  const rowCenter = w => (w.bbox.y0 + w.bbox.y1) / 2;
  const rowHeight = w => (w.bbox.y1 - w.bbox.y0);
  const keywordWords = words.filter(w => w.text && RECEIPT_KEYWORDS.some(kw => fullWidthDigitsToHalf(w.text).includes(kw)));
  for(const kw of keywordWords){
    const kwY = rowCenter(kw);
    const tolerance = rowHeight(kw) * 0.6 + 4;
    const rowWords = words
      .filter(w => w !== kw && Math.abs(rowCenter(w) - kwY) <= tolerance)
      .sort((a,b) => a.bbox.x0 - b.bbox.x0);
    for(const w of rowWords){
      const amount = parseAmountToken(w.text);
      if(amount !== null) return amount;
    }
  }
  return null;
}
```

### 検証結果(v0.6.1)

「小計¥1,200」「消費税¥96」「合計¥1,296」「お預り¥2,000」「お釣り¥704」を
ラベルと金額を大きく離して配置した合成レシート画像で検証。
**お預り(2,000)が合計(1,296)より大きい値であっても、正しく「合計」行の
1,296を抽出できることを確認**(単純な最大値採用ではないことの実証)。

## 6. データモデルへの影響

**なし。** レシート画像自体は記録データに永続化しない(OCR処理が終わったら破棄)。
理由:
- 既存のレコードスキーマ(`id/date/category/subCategory/amount/memo/createdAt/updatedAt`)を
  変更せずに済む
- 画像をlocalStorageにBase64で保存すると1件あたり数百KB〜数MBになり得て、
  localStorageの容量上限(ブラウザにより5〜10MB程度)をすぐに圧迫する
- 本機能の目的は「金額入力の手間を減らすこと」であり、レシート画像の保管・閲覧は
  別スコープ(将来必要になった場合はIndexedDB等への切替を伴う別機能として再検討)

## 7. エラーハンドリング・フォールバック

| ケース | 挙動 |
|---|---|
| オフライン(Tesseract.js本体・言語データがCDNから取得できない) | 「オフラインのためレシート読取は利用できません。手入力してください」を表示し、通常の手入力フローへ |
| OCRは成功したが金額が抽出できない | 金額欄は空のまま、「金額を読み取れませんでした。手入力してください」を表示 |
| OCR自体が例外を投げる | 同上のメッセージでフォールバック、`console.error` に詳細を出力 |
| 抽出した金額が明らかに不自然(例: 0円、上限超え) | 抽出ロジック内で除外(`10〜1,000,000`の範囲外は候補にしない) |

いずれの場合も、既存の「手入力して記録する」フローは常に利用できる状態を維持する
(レシート読取はあくまで補助機能であり、必須の経路にしない)。

## 8. 制約・既知の限界

- OCR精度は完全ではない(特に店名・品目名などの文字部分)。金額(数字)の認識は
  比較的精度が高いが、桁の誤認識等の可能性はゼロではないため、**自動入力後の
  ユーザー確認は必須**とする
- 初回利用時にTesseract.js本体+日本語学習データ(合計 数MB程度)をCDNから
  取得するため、回線状況によっては読込みに時間がかかる場合がある
- 現状のService Worker(`sw.js`)はCDN(cross-origin)リクエストを積極的に
  キャッシュする設定にしていないため、オフライン時はレシート読取機能自体が
  使えない(手入力へのフォールバックで対応。将来的にCDNアセットのキャッシュ
  対応を追加する余地はある)
- レシートのレイアウト(改行位置、フォント、感熱紙の掠れ等)によって抽出精度は
  変動する。「合計」表記が無いレシートやフォーマットが大きく異なる場合は
  フォールバック(最大値採用)の精度がさらに下がる可能性がある

## 9. 実装結果(v0.6.0)

上記仕様に基づき `docs/index.html` に実装済み。

- `#entryModal` にレシート読込ボタン・ファイル入力・ステータス表示・サムネイル表示を追加
- `loadTesseract()` / `extractAmountFromText()` / ファイル選択時のOCR実行処理を実装
- ローカルサーバー + 合成レシート画像(File/DataTransfer経由でファイル入力に注入)による
  動作検証を実施し、「合計」金額の自動抽出→金額欄反映→大項目選択→記録可能な状態まで
  一連のフローが正しく動作することを確認
- モーダルを閉じる/記録した際にサムネイル用のobject URLを破棄し、再度開いたときは
  レシート関連UIが初期状態にリセットされることを確認
