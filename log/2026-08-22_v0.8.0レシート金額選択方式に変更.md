# 2026-08-22 spending-log v0.8.0 レシートOCR: 金額の決定方式を選択式に変更

## 概要
v0.6.0〜v0.7.2で「合計」等のキーワードに基づき自動的に金額を1つに絞り込む
方式を実装・改良してきたが、都度異なるOCR誤認識パターン(カンマ分断・
キーワード分割等)への対応が必要になり、根本解決に至らなかった。
ユーザーより下記の仕様変更の指示があり、方式そのものを見直した。

- トリミング機能自体は残す
- トリミング範囲を拡大する
- トリミングした範囲内の¥に紐づく金額をすべて列挙する
- 列挙された中からユーザーが記録したいものを選択する
- 選択した金額を金額として保存する

## 変更内容
`docs/index.html`

- `extractAllAmountCandidates(text)` を新設。「¥」(OCRが誤認識しやすい
  "\"も許容)に紐づく数字を全て抽出し、重複を除いて出現順に列挙する
- 新規モーダル `#receiptAmountListModal`: 列挙された金額をタップ可能な
  一覧(既存の`.daylist-row`スタイルを流用)として表示し、タップした金額を
  `#amountInput` に反映する
- `openCropModal` の初期選択範囲を拡大(画像のほぼ全体を初期選択済みに)
- レシート読込ボタンの文言を「(金額を自動入力)」→「(候補から選択)」に変更
- 不要になった旧来のキーワードベース抽出コード一式を削除:
  `RECEIPT_KEYWORDS` / `isRegistrationNumberToken` / `isRegistrationLabelToken` /
  `groupWordsIntoRows` / `extractAmountFromWords` / `extractAmountFromText` /
  `extractSingleAmountCandidate` / `parseAmountToken`
  (¥記号を手がかりにするため、登録番号は¥が付かず自然に候補から外れる
  ようになり、専用の除外ロジックが不要になった)

## 検証
- `extractAllAmountCandidates` が複数行のテキストから金額を正しく列挙する
  ことを確認(例: 小計/消費税/合計/お預りの4件を全て列挙)
- カンマ分断のケース(「合計 ¥4, 010」)でも `4010` として正しく列挙されることを確認
- 実際にTesseract.jsでOCRした合成画像で、選択→トリミング確定→OCR→
  候補一覧表示→タップ選択→金額欄反映、という一連のフローが正しく
  動作することを確認(4件の候補表示、選択した¥1,296が金額欄に反映)
- 候補が見つからない場合のメッセージ表示を確認
- モーダルを閉じて再度開いた際のリセット動作を確認
