# 2026-08-22 spending-log v0.5.3 タブスワイプの反応改善

## 概要
v0.5.2で「タブ1のスワイプ遷移はできるようになったが反応が鈍い」との報告。
v0.5.1で採用した「カレンダー内スワイプは130px以上でタブ切替」という距離ベースの
区別方式が、実用上は大きすぎる距離を要求しており、体感の反応が悪くなっていた。

## 修正内容
`docs/index.html`
- 月切替とタブ切替の区別方法を「スワイプ距離」から「スワイプの開始位置」に変更
  - 画面端付近(`EDGE_ZONE = 32px` 以内)から始まったスワイプ → タブ切替
  - それ以外(グリッド中央側)から始まったスワイプ → 月切替(従来通り)
  - カレンダー外で始まったスワイプは従来通り常にタブ切替
- しきい値を `CAL_MONTH_SWIPE_MIN = 50px` / `TAB_SWIPE_MIN = 60px` の
  小さい値に統一(旧: タブ切替は130px以上必要だった)
- カレンダーグリッド専用だった旧スワイプ処理(`#calGrid` 単体のtouchstart/touchend)を
  main全体のスワイプハンドラに統合し、ロジックを一本化
- `<meta name="app-version">` を `0.5.3` に更新
- `CHANGELOG.md` に `[0.5.3]` のエントリを追加

## 検証
ローカルの `py -3 -m http.server` 配信 + Claude Browserのモバイルビューポート上で
`TouchEvent`/`Touch` を合成発火させ、以下4パターンを確認(いずれも意図通り):
1. カレンダー中央付近・短いスワイプ(dx=-80)→ 月切替のみ
2. カレンダー左端付近(EDGE_ZONE内)・短いスワイプ(dx=-80)→ タブ切替のみ
3. カレンダー右端付近(EDGE_ZONE内)・短いスワイプ(dx=+80、タブ1から)→
   切替先がない境界のため変化なし(想定通りの境界動作)
4. カレンダー外(ヘッダー付近)・短いスワイプ → タブ切替(既存動作を維持、回帰なし)
