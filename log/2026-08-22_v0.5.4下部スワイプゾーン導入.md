# 2026-08-22 spending-log v0.5.4 タブ切替を画面下部の専用ゾーンに変更

## 概要
ユーザーより「スワイプは画面下部に判定を置くことに変更」「全てのタブで共通とする」との
指示。v0.5.1〜v0.5.3で試みた「カレンダー内スワイプの距離/開始位置による月切替との
判定分岐」方式をやめ、タブ切替専用の領域を画面下部に新設する方式に変更した。

## 変更内容
`docs/index.html`

### HTML
- `<main>` の直後、モーダル群より前に、画面下部固定の専用スワイプゾーンを追加:
  `<div class="swipe-zone" id="swipeZone" aria-hidden="true"><span class="swipe-handle"></span></div>`
  - `main` の外(タブパネルの外)に配置しているため、タブの中身に関係なく常に同じ
    場所に存在し、全タブで共通の挙動になる

### CSS
- `.swipe-zone`: `position:fixed; bottom:0;`、高さ56px、`env(safe-area-inset-bottom)`
  分の余白、上部に薄いボーダー、背景は `--surface`
- `.swipe-handle`: 中央に幅36px・高さ4pxの「つまみ」インジケーターを表示し、
  スワイプ可能な領域であることを視覚的に示す
- `body` の `padding-bottom` を `calc(64px + env(safe-area-inset-bottom))` に変更し、
  下部ゾーンの分だけ本文コンテンツと重ならないよう余白を確保

### JS
- カレンダー内(`#calGrid`)のスワイプ処理を、月切替のみを行う単純な形に戻した
  (v0.5.1〜v0.5.3で追加していた「タブ切替との距離/位置による分岐」ロジックは撤廃)
- タブ切替のスワイプ処理を `main` 全体ではなく `#swipeZone` 単体に付け替え。
  ロジックも「開始位置がカレンダー内か・画面端か」といった分岐が不要になり
  大幅にシンプル化(距離のみで判定: `TAB_SWIPE_MIN = 50px`)
- 不要になった `EDGE_ZONE` 定数を削除

## 検証
ローカルの `py -3 -m http.server` 配信 + Claude Browserのモバイルビューポート上で
`TouchEvent`/`Touch` を合成発火させ、以下4パターンを確認(いずれも意図通り):
1. タブ1・カレンダー中央でのスワイプ → 月切替のみ(タブは変わらない)
2. タブ1・下部ゾーンでのスワイプ → タブ切替のみ(月は変わらない)
3. タブ2・下部ゾーンでのスワイプ → タブ切替(全タブ共通であることを確認)
4. タブ3・下部ゾーンでの逆方向スワイプ → タブ切替(全タブ共通であることを確認)
