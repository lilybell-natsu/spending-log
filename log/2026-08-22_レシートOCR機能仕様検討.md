# 2026-08-22 spending-log レシートOCR機能の仕様検討・方式確立

## 概要
「レシートの画像を読み込ませる→金額を読み取る→大項目と小項目を選択→記録」という
新機能について、実装に先立ち仕様の検討と方式の確立を行った(実装は未着手)。
指示に基づき、コミット・pushまで実施。

## 検討した方式
| 方式 | 採否 | 理由 |
|---|---|---|
| クラウドOCR API(Google Cloud Vision等) | ✕ | バックエンド無し・APIキー露出リスク |
| ブラウザ標準 Shape Detection API | ✕ | iOS Safari非対応 |
| Tesseract.js(クライアントサイドOCR) | ○ 採用 | バックエンド不要、画像は端末外に送信されない |

## 技術検証(プロトタイプ)
- 日本語混じりの合成レシート画像(小計/消費税/合計/お預り/お釣りを含む)を
  canvasで生成し、Tesseract.js(CDN経由, `jpn`言語データ)で実際にOCRを実行
- 認識結果からキーワード(「合計」優先)ベースの抽出ロジックで金額を取得するテストを実施
- 結果: 正しく「合計」の値(810)を抽出できることを確認(小計750やお預り1,000ではない)
- 所要時間: 約4.9秒(ライブラリ・言語データのロード含む)
- 検証用ファイルはスクラッチディレクトリに作成し、リポジトリには含めていない
  (`.claude/launch.json` のテスト用サーバー設定も検証後に削除済み)

## 方針のポイント
- レシート画像自体は記録データとして保存しない(OCR用途のみ、処理後は破棄)
- 自動読取した金額は必ずユーザーが確認・修正できる状態にする(自動記録はしない)
- オフライン時やOCR失敗時も、既存の手入力フローに必ずフォールバックできるようにする
